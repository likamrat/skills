# Reference decks

Treat every supplied PPTX as untrusted until inspected. A reference deck is design grammar only, never the mutable output base. Start every editable output from a copy of the bundled clean PowerPoint seed.

## Inspect

Record:

- package warnings, macros, OLE, external relationships, and links;
- slide size, sections, masters, layouts, themes, fonts, notes, and hidden slides;
- representative cover, section, comparison, process, architecture, data/table, decision, and closing slides.

## Extract design grammar

Capture:

- safe margins and title baseline;
- type sizes, weights, and line lengths;
- palette roles rather than raw colors alone;
- recurring grids and slide families;
- card, table, chart, connector, and image geometry;
- footer, notes, and confidentiality;
- transition and animation behavior.

## Authorization scopes

- `design-language-only`: reproduce hierarchy, density, spacing, rhythm, and component logic with original elements.
- `approved-asset-reuse`: use only the named approved assets.
- `none`: do not use the reference.

Sharing a file permits inspection, not automatic redistribution of its content or assets. Even under `approved-asset-reuse`, import only the approved assets into the seed-based output; do not copy or mutate the reference package into the deliverable.

## Compare

Render output and representative reference slides side by side. Compare design behavior, not prose. Check slide size, hierarchy, density, alignment, spacing, geometry, and rhythm.
